# 打印机租赁运营业务规则总文件

> 本文档是打印机租赁业务的最终业务规则，面向「企业微信智能表 + WorkBuddy」日常运营。
> 只使用业务语言，不含技术实现细节。不读任何代码，仅通过本文档即可理解业务如何运营。
> 本文档是 `WORKBUDDY_LEDGER_SCHEMA.md`（台账结构）与 `WORKBUDDY_PRINTING_SKILL.md`（WorkBuddy 操作方式）的业务依据；三份文档以本文档为准。

---

## 0. 业务模式

我们是打印机租赁中间商（运营方）：

- 向**客户**收取租金与超印费（客户应收）；
- 向**供应商**支付设备与服务的采购成本（供应商应付）；
- 差额为**运营毛利**。

每台在客户现场的打印机都是一笔「客户侧收入 − 供应商侧成本」的小生意。业务数据必须能回答任意一台设备：谁在用、放在哪、什么套餐、哪张订单、哪个供应商、什么型号、何时进退场、用了多少、该收多少、该付多少。

## 1. 主数据

### 1.1 Customer（客户）

客户是向我们租赁打印服务的企业。

- **客户编码**：自动生成，从 C0001 起按序递增（不足 4 位补零），创建后不可修改。
- **必要信息**：客户名称。
- **可选信息**：客户类型（内部 / 外部，无运营价值时可以不填）、纳税人识别号、注册地址、银行名称 / 户名 / 账号、联系人、备注。
- 注册地址是公司工商 / 合同地址，与打印机实际安装地址是两回事。
- **客户类型不影响任何业务流程**：不知道客户是内部还是外部，也必须能正常创建客户与订单。

### 1.2 Supplier（供应商）

供应商是向我们提供打印设备与服务的企业（设备实际所有者 / 服务方）。

- **供应商编码**：自动生成，从 S0001 起按序递增，规则与客户编码相同。
- **必要信息**：供应商名称。
- **可选信息**：税号、注册地址、银行资料、联系人、服务区域、备注。

### 1.3 MachineModel（机型库）

- 一条机型 = 品牌 + 型号（组合唯一）。
- **设备类型**只有两种：
  - **黑白机**：只抄黑白读数，没有彩色读数。
  - **彩色机**：同时记录黑白读数与彩色读数。
- 被任何设备引用过的机型不能删除。

### 1.4 Package / Package Version（套餐与套餐版本）

套餐是计费的价格条款，包含三个价格要素：

- **月租**（元 / 月）
- **每月免费 BW Equivalent 额度**
- **超印单价**（元 / BW Equivalent）

套餐分两侧：

- **客户套餐**：计算客户应收。归属客户为空 = **标准套餐**（所有客户可用）；归属某个客户 = **客户专属套餐**。
- **供应商套餐**：计算供应商应付，必须归属一个供应商。**供应商侧价格由运营方（我们）自行维护**：与供应商议价后由运营方新建版本更新，不向供应商开放维护入口。

套餐可关联多个适配机型。

**版本规则**：

- 价格创建后**不可直接修改**。
- 重新议价 = 原套餐编码下**新建版本**（V2、V3…），原版本保留、可停用。
- 同一套餐编码下版本号唯一；历史业务永远引用当初的版本。

### 1.5 固定换算规则

- 1 张黑白 = **1 BW Equivalent**
- 1 张彩色 = **10 BW Equivalent**

该换算比例**长期固定不变**（2026-09 人工确认）。BW Equivalent 是计费与免费额度的统一计量单位。

## 2. Order（订单）

### 2.1 订单定义

**一张订单 = 一次完整的租赁交易**：一个客户 + 一个安装地址 + 一个供应商 + 若干套餐明细，外加租期、结算方式、押金与文件。

订单包含：

- 订单号（自动生成）：「下单当天日期 + 当日序号」，YYYYMMDD + 01 起递增，全局唯一。
- 客户（创建后不可改）、供应商、安装地址（手填文本）。
- 开始日期（必填）/ 结束日期。
- 结算方式：按月结算 / 按自然季度结算。
- 押金应收（自动计算）、押金收款日期。
- 下单日期（默认当天）。
- 合同文件、订单附件（两个独立文件槽，均可空）。
- 状态、备注。

### 2.2 一张订单的边界

- 一张订单属于**一个客户、一个安装地址、一个供应商**。
- 同一客户在不同安装地址的部署，是**不同的订单**。
- 同一客户在同一地址、不同时间新增设备，也是**新的订单**（见 2.4）。
- 订单明细描述「这次交易订了几台、各用什么套餐」；设备实际进场后挂在订单明细之下。

### 2.3 多套餐规则

- 一张订单可以有**多条订单明细**，每条明细 = 一个套餐 × 数量（数量 ≥ 1）。
- 明细选用的客户套餐必须对该客户可用（标准套餐或该客户专属套餐）。
- 部署进度（已部署 / 数量）由设备台账动态算出，不单独记录。

### 2.4 新增设备必须新建订单

- 客户要新增机器，**必须新建一张订单**（新客户、新地址同理）。
- **禁止**通过修改历史订单明细的数量来表示新增机器。

### 2.5 订单日期规则

- 开始日期必填。
- 结束日期默认 = **开始日期 + 3 年 − 1 天**。默认 3 年租期**适用于所有客户**（2026-09 人工确认），除非合同有特别标注；可人工修改，不得早于开始日期。
- 下单日期默认为当天。
- 没有第三个日期概念：**订单只有开始 / 结束日期，设备只有实际进场 / 退场日期**，不存在「计划进场日期」。

### 2.6 订单状态

四个状态：**草稿 → 履约中 → 已结束**，另有**已取消**。

- **结束订单**：只改状态，**不触碰**任何设备、抄表、结算历史；有运行中设备也允许结束（提示后由人确认）。
- **已取消的订单**不可再进场设备。
- 结束订单**不会自动撤机**。

### 2.7 押金规则（当前固定，不提前支持特殊押金）

- 押金固定：**每台设备人民币 2,000 元**。
- 押金应收 = 订单全部明细数量合计 × 2,000，自动计算。
- 押金收款日期：**空 = 尚未登记收款；有日期 = 已全额收到**。
- 当前阶段**不支持**：特殊押金、免押金、部分押金、分期押金、退款 / 抵扣。真实业务出现时再新增规则，不提前设计。

### 2.8 订单修改规则

- 可改：供应商、安装地址、起止日期、结算方式、下单日期、状态、备注、文件。不可改：客户。
- 明细保护：**已有设备进场的明细行，不能更换套餐、不能删除该行**（减设备先撤机）；新增明细行随时可加。

## 3. Printer（设备）

设备是业务最核心的对象：它把客户侧（客户 / 订单 / 套餐）和供应商侧（供应商 / 成本）连接在一台具体的机器上。

### 3.1 进场

设备进场需要：

- **所属订单明细**（客户、地址、套餐自动追溯，不重复填写）
- **机型**
- **进场日期**
- **初始读数**（黑白必填；彩色机还需彩色初始读数）

设备创建后即为「运行中」。一条明细下运行中的设备数达到明细数量后，不能再从该明细进场。供应商侧信息不是进场的前置条件（缺失只影响毛利计算，见 5.5）。

### 3.2 printerCode（设备编码，唯一一套编码）

每台设备**只有一个设备编码**，不维护「内部编号 + 供应商编号」两套：

- 供应商自己有机身编号 → **直接作为 printerCode**；
- 供应商没有编号 → 自动生成（P0001 起递增）。

规则：

- **不同供应商出现相同 printerCode 是允许的**。
- 设备的真正身份是台账记录的 **Record ID**，printerCode 只是日常识别用，不作为系统唯一主键。
- 查找 / 核对设备时结合 Record ID、所属订单、供应商、机型、状态一起判断；与运行中设备同编码时提示确认一次，避免混淆，但不强制拦截。

### 3.3 entryDate（进场日期）

- 首月结算按进场日起到月底的实际天数折算（进场当天计入）。
- 首月用量 = 首次抄表本期累计读数 − 进场初始读数。
- 不允许补录进场月份之前的抄表。

### 3.4 初始读数

- 进场时记录黑白初始读数（彩色机还要彩色初始读数）。
- 初始读数是用量计算的起点：首期用量 = 首期抄表读数 − 初始读数。

### 3.5 设备状态与生命周期

状态：**运行中 / 已换机 / 已撤机**。

- 只有「运行中」的设备可以抄表、换机、撤机。
- 「已换机」「已撤机」的设备：**记录永久保留、不物理删除、不修改**，历史抄表完整可查。

### 3.6 换机

换机只用于**原机故障 / 损坏 / 技术原因替换**，不是新增业务。一次换机：

- 旧设备：状态 → 已换机，退场日期 = 换机日期。
- 新设备：新建记录，进场日期 = 换机日期，状态「运行中」，记录「上一台设备 = 旧设备」，重新填写机型、设备编码、新初始读数。
- 客户订单明细**沿用原机**。
- 换机日期不得早于原机进场日期；旧设备历史抄表原样保留。

### 3.7 撤机

- 仅运行中设备可撤机；填写撤机日期（不得早于进场日期），状态 → 已撤机。
- 撤机后不能再产生新抄表；退场当月及以前的在役月份仍可补录历史抄表（见 4.5）。

## 4. MeterReading（抄表）

### 4.1 只保存真正的业务事实

一条抄表记录只保存：**设备、业务年月、本期黑白累计读数、本期彩色累计读数（彩色机）、抄表照片、状态、调整说明、操作人（可选）**。

以下内容**不是业务事实，一律不人工维护、不存台账**，由智能表公式或 WorkBuddy 根据历史记录与初始读数现算：

- 上期读数、黑白 / 彩色用量、BW Equivalent 用量、一切结算金额。

用量推导：

- **首期**：本期累计 − 设备初始读数。
- **后续期**：本期累计 − 上一期正式抄表的本期累计。

### 4.2 业务月份与唯一性

- 抄表按**自然月**归属；**一台设备一个自然月只能有一条正式抄表**。要修正就修改原记录，不产生第二条。

### 4.3 抄表窗口（客户扫码）

- 客户通过设备二维码免登录提交：**每月 1 日至 3 日**提交**上一自然月**的读数。（窗口规则暂时保留，后期可能调整——2026-09 人工确认。）
- 每月 4–25 日：本期已关闭；每月 26 日起：下一期尚未开放。
- 已换机 / 已撤机设备扫码只提示「已停止使用」；本期已提交的不能二次提交，只能由管理员修改。
- 客户扫码提交**必须上传抄表照片**。

### 4.4 读数规则

- 提交的是**累计表读数**（表显总数），不是用量。
- 黑白机没有彩色读数；彩色机必须填彩色读数。
- BW Equivalent 用量 = 黑白用量 + 彩色用量 × 10（衍生值，见 4.1）。

### 4.5 新增 / 编辑 / 补录（管理员与 WorkBuddy）

不受客户抄表窗口限制：

- **新增**：填年月与本期累计读数；照片与备注可选。允许当前月与历史月份，**不允许未来月份**。
- **编辑**：在原记录上修改读数，必须填写调整说明，状态变「已调整」；不删除重建。
- 同一设备同一月份仍然唯一。
- 补录范围：**进场月份 ≤ 抄表月份 ≤ 退场月份**（未退场则至当前月）。

### 4.6 累计读数校验

- **本期读数不得低于上一期**（上一期 = 目标月之前最近一条正式抄表；没有更早抄表时 = 进场初始读数），黑白 / 彩色分别校验。
- 目标月之后已有抄表时，**本期读数不得高于下一期读数**。
- 例：8 月 10,000、10 月 20,000，则补录 9 月必须在 10,000–20,000 之间。

### 4.7 修改历史读数 = 后续用量实时重算

- 用量是衍生值，不是独立业务事实。修改历史累计读数（如 7 月 7,000 改成 8,000）后，**所有依赖它的后续期用量必须按最新累计读数重新计算**（8 月用量 = 8 月累计 − 修改后的 7 月累计）。
- 当前没有财务封账、正式结算锁定、已开票金额锁定，因此**保持实时重算**，不保留旧用量结果。
- 未来若引入正式财务结算 / 封账，再单独增加锁定规则。

### 4.8 免费额度逐机独立

每月免费额度**按每台设备独立计算、逐月折算**，不在设备之间共享、不汇总池化。

## 5. Settlement（结算）

### 5.1 计算原则（单台设备 × 单个自然月）

对每台设备、每个自然月，客户侧与供应商侧用各自的套餐分别计算同一套公式：

1. **在场天数**：进场当天计入，退场当天不计入；当月不在场（0 天）则当月不产生结算。
2. **实际月租** = 月租 × 在场天数 ÷ 当月天数。
3. **实际免费额度** = 每月免费额度 × 在场天数 ÷ 当月天数。
4. **超印量** = MAX(BW Equivalent 用量 − 实际免费额度, 0)。
5. **超印费** = 超印量 × 超印单价。
6. **当月金额** = 实际月租 + 超印费。

金额保留两位小数（四舍五入）。**客户应收**用客户套餐算，**供应商应付**用供应商套餐算，**运营毛利** = 客户应收 − 供应商应付。

示例：月租 450、免费额度 10,000、超印 0.03，设备 9 月 20 日进场（在场 11 天 / 9 月 30 天）：实际月租 = 450 × 11 / 30 = 165，实际免费额度 = 10,000 × 11 / 30。

### 5.2 月结

每台设备按其**最近一个抄表月份**出当月结算；订单层面把同一最近月份各台设备金额加总。

### 5.3 自然季度结算

- 自然季度固定为 Q1（1–3 月）、Q2（4–6 月）、Q3（7–9 月）、Q4（10–12 月）。
- 先把每台设备该季度内**各月的月度结算**逐字段求和（中途进退场由各月按天折算自然体现），再把各台设备的最近季度加总到订单。
- 季度结算只是**三个月度结果相加**；免费额度仍按每台设备逐月独立折算，不整季合并、不跨机共享。

### 5.4 结算的性质

- 结算是**基于抄表与套餐的实时计算结果**，随最新抄表自动变化；**不在台账中保存结算金额**。
- 当前不产生独立「结算单」存档，不含开票、回款等正式财务环节。

### 5.5 供应商侧缺失时的处理

- 设备可能没有配置供应商侧价格。此时**客户应收照常计算**；供应商应付与毛利标记为「未配置 / 暂不可计算」。
- 订单汇总时有一台缺供应商价格，整个订单的应付与毛利不可汇总，客户应收照常汇总。
- 供应商侧信息缺失**永远不阻塞客户侧业务**；由运营方后续补录供应商套餐版本。

## 6. 通用运营原则

### 6.1 历史数据保护（红线）

- 已换机 / 已撤机设备：不物理删除、不修改。
- 历史抄表：只在原记录上修正（留调整说明），不删除重建；修正后衍生用量实时重算（见 4.7）。
- 历史套餐版本：不覆盖、不删除，只能停用并新建版本。
- 被设备引用的机型、被订单引用的客户 / 供应商 / 套餐：不删除。
- 有设备的订单不删除；结束订单不改变任何设备与抄表历史。
- 台账记录正常递增编号即可，不做复杂的历史编号 / 复用系统。

### 6.2 管理员可修改

管理员拥有最终修改权，受完整性规则约束：

- 订单：除客户外均可改；有设备的明细行不可换套餐、不可删行。
- 抄表：可补录、可修正（留调整说明）。
- 设备：运行中设备可改编码、机型、进场日期、初始读数、备注；历史设备不可改。

### 6.3 什么信息可以为空

- 客户类型、税号、地址、银行、联系人、备注。
- 订单的结束日期（有默认规则）、押金收款日期（= 未登记收款）、合同文件、订单附件、备注。
- 抄表的照片与备注（仅后台补录场景；客户扫码照片必传）。

### 6.4 什么信息不能猜

以下信息缺失时必须向人核实，不得自行编造：

- 一台设备属于哪个客户、哪个订单、哪个安装地址。
- 价格条款（月租、免费额度、超印单价）与套餐版本归属。
- 任何读数（初始读数、抄表读数）。
- 任何日期（进场、退场、换机、起止、押金收款日）。
- 押金是否已收。
- 机型与设备类型（黑白 / 彩色）。
- 供应商身份。

### 6.5 资料冲突时的处理

- 同一业务事实出现两个不同说法时，**不得自行选择一个写入**；把冲突项与来源一次性列给用户裁定。
- 台账已有历史事实（历史抄表、历史价格版本、进退场记录）默认受保护，只有用户明确确认后才修正，修正必须留痕。
