# 打印机租赁运营业务规则总文件

> 本文档提炼自已确认的产品规则与打印机租赁运营平台 Web V1（TASK 01–19）的真实实现。
> 只使用业务语言，不含技术实现细节。目标是：不读任何代码，仅通过本文档即可理解打印机租赁业务如何运营。
> 本文档是 `WORKBUDDY_LEDGER_SCHEMA.md`（台账设计）与 `WORKBUDDY_PRINTING_SKILL.md`（WorkBuddy 操作规范）的业务依据。

## 0. 业务模式

我们是一家打印机租赁中间商（运营方）：

- 向**客户**收取租金与超印费（客户应收）；
- 向**供应商**支付设备与服务的采购成本（供应商应付）；
- 差额为**运营毛利**。

每台在客户现场的打印机都是一笔「客户侧收入 − 供应商侧成本」的小生意。业务数据必须能回答任意一台设备：谁在用、放在哪、什么套餐、哪张订单、哪个供应商、什么型号、何时进退场、用了多少、该收多少、该付多少。

## 1. 主数据

### 1.1 Customer（客户）

客户是向我们租赁打印服务的企业。

- **客户编码**：系统自动生成，从 C0001 起按序递增（不足 4 位补零），创建后不可修改，已删除客户用过的编码不复用。
- **必要信息**：客户名称、客户类型（内部 / 外部）。
- **可选信息**：纳税人识别号、注册地址、银行名称 / 户名 / 账号、联系人姓名 / 电话、备注。
- 注册地址是公司工商 / 合同地址，与打印机实际安装地址是两回事，互不相同。
- 有套餐或订单的客户不能被删除。

### 1.2 Supplier（供应商）

供应商是向我们提供打印设备与服务的企业（设备实际所有者 / 服务方）。

- **供应商编码**：系统自动生成，从 S0001 起按序递增，规则与客户编码相同。
- **必要信息**：供应商名称。
- **可选信息**：纳税人识别号、注册地址、银行资料、联系人、服务区域、备注。
- 有套餐或订单关联的供应商不能被删除。

### 1.3 MachineModel（机型库）

机型库是打印机的标准产品目录。

- 一条机型 = 品牌 + 型号（品牌 + 型号组合唯一）。
- **设备类型**只有两种：
  - **黑白机**：只抄黑白读数，禁止提交彩色读数。
  - **彩色机**：同时记录黑白读数与彩色读数。
- 被任何设备引用过的机型不能被删除。

### 1.4 Package / Package Version（套餐与套餐版本）

套餐是计费的价格条款，包含三个价格要素：

- **月租**（元 / 月）
- **每月免费 BW Equivalent 额度**
- **超印单价**（元 / BW Equivalent，超出免费额度部分按此计费）

套餐分两侧：

- **客户套餐**：用于计算客户应收。归属客户为空时是**标准套餐**，所有客户可用；归属某个客户时是**客户专属套餐**，只有该客户可用。
- **供应商套餐**：用于计算供应商应付，必须归属一个供应商。**供应商侧价格由运营方（我们）负责维护**（2026-09 人工确认）：与供应商议价后由运营方在套餐表中新建版本更新，不向供应商开放维护入口。

套餐可以关联多个适配机型（一台设备选用的套餐应当适配其机型）。

**版本规则（重要）**：

- 价格创建后**不可直接修改**。
- 重新议价 = 在原套餐编码下**新建一个版本**（V2、V3…），原版本保留、可停用。
- 同一套餐编码下版本号唯一。
- 历史订单 / 历史业务永远引用它当初使用的那个版本，不因新版本而变化。

### 1.5 固定换算规则

整个业务体系统一：

- 1 张黑白 = **1 BW Equivalent**
- 1 张彩色 = **10 BW Equivalent**

该换算比例**长期固定不变**（2026-09 人工确认）。

BW Equivalent（黑白等价用量）是计费与免费额度的统一计量单位。

## 2. Order（订单）

### 2.1 订单定义

**一张订单 = 一次完整的租赁交易**：一个客户 + 一个安装地址 + 一个供应商 + 若干套餐明细，外加租期、结算方式、押金与文件。

订单包含：

- 订单号（自动生成，见下）
- 客户（创建后不可改）
- 供应商
- 安装地址（手填文本，即设备实际部署地点）
- 开始日期（必填）/ 结束日期
- 结算方式：按月结算 / 按自然季度结算
- 押金应收（自动计算）、押金收款日期
- 下单日期（默认当天）
- 合同文件、订单附件（两个独立文件槽）
- 状态、备注

**订单号**：不由人工填写。格式为「下单当天日期 + 当日序号」：YYYYMMDD + 01 起递增（如 2026 年 9 月 16 日第一张是 2026091601）。全局唯一，已删除订单的编号不复用。

### 2.2 一张订单的边界

- 一张订单属于**一个客户、一个安装地址、一个供应商**。
- 同一客户在不同安装地址的部署，是**不同的订单**。
- 同一客户在同一地址、不同时间新增设备，也是**新的订单**（见 2.4）。
- 订单明细描述「这次交易订了几台、各用什么套餐」；设备（Printer）实际进场后挂在订单明细之下。

### 2.3 多套餐规则

- 一张订单可以有**多条订单明细**，每条明细 = 一个套餐 × 数量（数量 ≥ 1）。
- 明细选用的客户套餐必须对该客户可用（标准套餐或该客户专属套餐）。
- 例：一张订单可以是「套餐 A × 10 台 + 套餐 B × 3 台」。
- 部署进度按明细逐条统计：已部署台数 / 数量（未部署 / 部分部署 / 已部署），由设备台账动态算出，不单独记录。

### 2.4 新增设备必须新建订单

- 客户要新增机器，**必须新建一张订单**（新客户、新地址同理）。
- **禁止**通过修改历史订单明细的数量来表示新增机器。历史数量只代表当时的交易事实。

### 2.5 订单日期与默认 3 年规则

- 开始日期必填。
- 结束日期默认 = **开始日期 + 3 年 − 1 天**（如 2026-10-01 → 2029-09-30）。默认 3 年租期**适用于所有客户**（2026-09 人工确认），除非合同有特别标注；可以人工修改，但不得早于开始日期。
- 下单日期默认为当天，管理员可改。

### 2.6 订单状态

四个状态：**草稿 → 履约中 → 已结束**，另有**已取消**。

- **结束订单**：只把订单标记为「已结束」，**不触碰**任何设备、抄表、结算历史。即使订单下仍有运行中的设备也允许结束（系统只做风险提示，由管理员确认）。
- **已取消的订单**不可再进场设备。
- 结束订单**不会自动撤机**；设备要退出必须单独走撤机流程。

### 2.7 押金规则

- 押金为固定业务规则：**每台设备人民币 2,000 元**（2026-09 人工确认）。
- 押金应收 = 订单全部明细数量合计 × 2,000，保存订单时自动算出。
- **特殊情况允许人工调整押金金额**（如大客户免押金、按单议价），由管理员直接在订单上修改并留备注说明原因。
- **押金收款日期**记录实际收款：为空 = 未收；有值 = 已收（日期即收款日）。
- 历史订单的收款状态未知时保持「未收」，由人工核实后补录，不得猜测。

### 2.8 订单修改规则（管理员可改）

- 可改：供应商、安装地址、起止日期、结算方式、下单日期、状态、备注、文件。
- 不可改：客户。
- 明细保护：**已经有设备进场的明细行，不能更换套餐、不能删除该行**（要减设备须先对设备撤机 / 换机）；调低数量只做风险提示，不硬性阻止；新增明细行随时可以加。

## 3. Printer（设备）

设备是整个业务最核心的对象：它把客户侧（客户 / 订单 / 套餐）和供应商侧（供应商 / 成本）连接在一台具体的机器上。

### 3.1 进场

设备进场（创建）需要：

- **所属订单明细**（决定客户、地址、套餐，自动追溯，不重复填写）
- **机型**
- **进场日期**
- **初始读数**（黑白初始读数必填；彩色机还需彩色初始读数）

不需要重复选择客户、地址、合同、套餐——全部由订单明细自动带出。设备创建后即为「运行中」。

**部署容量**：一条明细下运行中的设备数达到明细数量后，不能再从该明细进场。

**供应商侧信息不是进场的前置条件**：设备可以在没有供应商订单关联的情况下进场（供应商侧成本数据缺失只影响毛利计算，不阻塞客户业务，见 5.5）。

### 3.2 printerCode（设备编码）

编码解析优先级：

1. 人工填写的编码；
2. 供应商资产编码；
3. 系统自动生成（P0001 起递增，不复用已删除设备的序号）。

编码**不做全局唯一强制**（不同供应商可能使用相同的资产编号），但**与「运行中」设备重名时会被拒绝并提示**；仅与历史设备重名不拦截。

**供应商资产编码**：可选字段，是供应商自己对设备的编号，留空不影响业务。

### 3.3 entryDate（进场日期）

进场日期是设备计费与抄表的起点：

- 首月结算按进场日起到月底的实际天数折算（进场当天计入）。
- 首月用量 = 首次抄表读数 − 进场初始读数。
- 不允许补录进场月份之前的抄表。

### 3.4 初始读数

- 进场时记录黑白初始读数（彩色机还要彩色初始读数）。
- 初始读数是该设备「上一期读数」的起点：第一期抄表的上期读数 = 初始读数。

### 3.5 设备状态与生命周期

状态：**运行中 / 已换机 / 已撤机**。

- 只有「运行中」的设备可以抄表、换机、撤机。
- 「已换机」「已撤机」的设备：**记录永久保留、不删除、不修改**，历史抄表完整可查。

### 3.6 换机

换机只用于**原机故障 / 损坏 / 技术原因替换**，不是新增业务。

一次换机 = 同一笔操作内完成：

- 旧设备：状态变「已换机」，退场日期 = 换机日期。
- 新设备：新建记录，进场日期 = 换机日期，状态「运行中」，并记录「上一台设备 = 旧设备」（换机链双向可查）。
- 重新填写：机型、设备编码、供应商资产编码、新初始读数（新设备从自己的初始读数重新起算用量）。
- 客户订单明细**沿用原机**（换机不改变客户买了什么）。
- 供应商侧默认沿用原机关联；供应商变化时可改挂新的供应商侧明细（该明细需有剩余容量且订单未取消）。
- 换机日期不得早于原机进场日期。
- 旧设备的历史抄表原样保留在旧设备名下。

### 3.7 撤机

- 仅运行中设备可撤机；填写撤机日期（不得早于进场日期）。
- 状态变「已撤机」，记录退场日期，数据保留不删除。
- 撤机后该设备不能再产生新抄表；退场当月及以前的在役月份仍可补录历史抄表（见 4.5）。

## 4. MeterReading（抄表）

### 4.1 业务月份与唯一性

- 抄表按**自然月**归属（如 9 月的用量记为 2026 年 9 月）。
- **一台设备一个自然月只能有一条正式抄表记录**。要修正就修改原记录，不产生第二条。

### 4.2 抄表窗口（客户扫码）

- 客户通过设备上的二维码免登录提交：**每月 1 日至 3 日**提交**上一自然月**的读数。（该窗口规则暂时保留，后期可能调整——2026-09 人工确认。）
- 每月 4–25 日：本期已关闭；每月 26 日起：下一期尚未开放。
- 已换机 / 已撤机设备扫码只提示「已停止使用」。
- 本期已提交过的，客户不能二次提交，只能由管理员修改。
- 客户扫码提交**必须上传抄表照片**。

### 4.3 读数规则

- 提交的是**累计表读数**（表显总数），不是用量。
- 用量 = 本期读数 − 上期读数；黑白 / 彩色分别计算；BW Equivalent 用量 = 黑白用量 + 彩色用量 × 10。
- **本期读数不得低于上期读数**（上期 = 该月之前最近一条抄表；没有更早抄表时 = 进场初始读数）。
- 黑白机没有彩色读数（视为 0），禁止填写彩色；彩色机必须填彩色读数。

### 4.4 新增 / 编辑 / 补录（管理员）

管理员可以不受抄表窗口限制地新增 / 修改正式抄表（客户未提交、读数错误、补历史月份等场景）：

- **新增**：填年份、月份、累计读数；照片与备注可选。允许当前月与历史月份；**不允许未来月份**。
- **编辑**：在原记录上修改读数（必须填写调整说明，记录操作人，状态变「已调整」），不删除重建。
- 同一设备同一月份仍然唯一。

### 4.5 补录范围

- 抄表月份必须落在设备在役期间内：**进场月份 ≤ 抄表月份 ≤ 退场月份**（未退场则无上限，但仍不得晚于当前月）。
- 已换机 / 已撤机设备可以补录其在役期间内的历史月份（含退场当月）。

### 4.6 前后期累计读数校验

新增或修改任何一条抄表时，读数必须与相邻期保持单调：

- **下界**：本期读数 ≥ 上一期累计读数（上一期 = 目标月份之前最近一条抄表，缺省为进场初始读数），黑白 / 彩色分别校验。
- **上界**：目标月份之后已有抄表时，本期读数 ≤ 下一期累计读数，黑白 / 彩色分别校验。
- 例：8 月读数 10,000、10 月读数 20,000，则补录 9 月必须在 10,000–20,000 之间。

### 4.7 免费额度逐机独立

每月免费额度**按每台设备独立计算、逐月折算**，不在设备之间共享、不汇总到订单层面池化。A 设备用不完的额度不能给 B 设备用。

## 5. Settlement（结算）

### 5.1 计算原则（单台设备 × 单个自然月）

对每台设备、每个自然月，客户侧与供应商侧用各自的套餐分别计算同一套公式：

1. **在场天数**：进场当天计入，退场当天不计入；当月不在场（0 天）则当月不产生任何结算。
2. **实际月租** = 月租 × 在场天数 ÷ 当月天数（按天折算）。
3. **实际免费额度** = 每月免费额度 × 在场天数 ÷ 当月天数（同样按天折算）。
4. **超印量** = MAX(BW Equivalent 用量 − 实际免费额度, 0)。
5. **超印费** = 超印量 × 超印单价。
6. **当月金额** = 实际月租 + 超印费。

金额保留两位小数（四舍五入）。

- **客户应收**：用该设备的客户套餐计算当月金额。
- **供应商应付**：用该设备的供应商套餐计算当月金额。
- **运营毛利** = 客户应收 − 供应商应付。

示例：月租 450、免费额度 10,000、超印 0.03 的套餐，设备 9 月 20 日进场（在场 11 天 / 9 月共 30 天），则实际月租 = 450 × 11 / 30 = 165，实际免费额度 = 10,000 × 11 / 30。

### 5.2 月结

按月结算的订单：每台设备按其**最近一个抄表月份**出当月结算；订单层面把同一最近月份各台设备金额加总，得到订单当月客户应收 / 供应商应付 / 毛利。

### 5.3 自然季度结算

按自然季度结算的订单：

- 自然季度固定为 Q1（1–3 月）、Q2（4–6 月）、Q3（7–9 月）、Q4（10–12 月）。
- 先把每台设备**该季度内各月**的月度结算逐字段求和（季度中途进场 / 退场由各月按天折算自然体现）；
- 再把各台设备的最近季度加总到订单。
- 注意：季度结算只是**把三个月的月度结果相加**，免费额度仍按每台设备逐月独立折算，绝不整季合并额度、不跨机共享。

### 5.4 结算的性质

- 结算是**基于抄表与套餐的实时计算结果**，随最新抄表数据自动变化；修正抄表后重新查看即为最新结果。
- 当前不产生独立的「结算单」存档，也不包含开票、回款等正式财务环节。

### 5.5 供应商侧缺失时的处理

- 设备可能没有关联供应商侧价格（供应商套餐未配置）。
- 此时：**客户应收照常计算**；供应商应付与毛利标记为「未配置 / 暂不可计算」。
- 订单汇总时，只要有一台设备缺供应商侧价格，整个订单的应付与毛利就不可汇总，但客户应收照常汇总。
- 供应商侧信息缺失**永远不阻塞客户侧业务**。

## 6. 通用运营原则

### 6.1 历史数据保护（红线）

- 已换机 / 已撤机设备：不删除、不修改。
- 历史抄表：只在原记录上修正（留痕），不删除重建。
- 历史套餐版本：不覆盖、不删除，只能停用并新建版本。
- 被设备引用的机型、被订单引用的客户 / 供应商 / 套餐：不能删除。
- 有设备的订单不能删除。
- 结束订单不改变任何设备与抄表历史。

### 6.2 管理员可修改

管理员拥有最终修改权，但修改受完整性规则约束：

- 订单：除客户外均可改；有设备的明细行不可换套餐、不可删行。
- 抄表：可补录、可修正（必须留调整说明）。
- 设备：运行中设备可改编码、资产编码、机型、进场日期、初始读数、备注；历史设备（已换机 / 已撤机）不可改。
- 数量调低、有运行中设备时结束订单等操作，系统给风险提示，由管理员确认负责。

### 6.3 什么信息可以为空

- 客户 / 供应商的税号、地址、银行、联系人、备注。
- 设备的供应商资产编码、供应商侧订单关联。
- 订单的结束日期（有默认规则）、押金收款日期（= 未收）、合同文件、订单附件、备注。
- 抄表的照片与备注（仅后台补录场景；客户扫码照片必传）。

### 6.4 什么信息不能猜

以下信息缺失时必须向人核实，不得自行编造：

- 一台设备属于哪个客户、哪个订单、哪个安装地址。
- 价格条款（月租、免费额度、超印单价）与套餐版本归属。
- 任何读数（初始读数、抄表读数）。
- 任何日期（进场、退场、换机、起止、押金收款日）。
- 押金是否已收。
- 机型与设备类型（黑白 / 彩色）。
- 供应商身份。

### 6.5 资料冲突时的处理

- 同一业务事实出现两个不同说法（如两份文件读数不同、日期不同）时，**不得自行选择一个写入**。
- 把冲突项与各方来源一次性列给用户，由用户裁定后再写入。
- 已有台账数据与新资料冲突时：台账中的历史事实（历史抄表、历史价格版本、进退场记录）默认受保护，只有用户明确确认后才能修正，修正必须留痕。
