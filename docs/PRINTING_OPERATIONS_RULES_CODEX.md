# 打印机租赁运营业务规则

版本：TASK 20，2026-09-23。适用于脱离 Web 平台后的人工运营与 WorkBuddy 台账操作。

依据：截至 TASK 19 的实际业务行为、开发进度中记录的人工确认规则，以及 TASK 11 评估报告。初版建议被后续明确确认修订的，采用后续确认；尚有冲突的，不自行裁决。本文只描述业务，不要求读者了解原项目。

配套文件：[智能表方案](WORKBUDDY_LEDGER_SCHEMA_CODEX.md)、[WorkBuddy 操作指令](WORKBUDDY_PRINTING_SKILL_CODEX.md)。规则编号长期保留，供配套文件引用。

## R01｜业务对象与主体

运营方向客户收取租金及超印费，向供应商支付设备与服务成本。客户应收减供应商应付为运营毛利；这不是净利润。

- **Customer（客户）**：租赁打印服务的业务主体。必要资料为名称、内部或外部类型；税号、注册地址、银行资料、联系人、电话、备注允许为空。注册地址不等于设备安装地址。
- **Supplier（供应商）**：提供设备或服务的上游业务主体。名称必要；税号、注册地址、银行资料、联系人、电话、服务区域、备注可空。供应商身份已知，不代表供应商价格已知。
- 客户、供应商可以启用或停用；停用不抹掉历史。已有业务引用的主体不删除。同名不能直接认定为同一主体，需结合编码、税号和来源判断。
- 客户编码通常为 C0001 起、供应商编码为 S0001 起，创建后不改；不复用已用编码是已确认规则，但当前平台存在 D04 所述限制。

## R02｜MachineModel（机型库）

一条机型表示一个品牌与型号组合，组合唯一；设备类型为黑白或彩色。品牌、型号和设备类型必须明确，不能仅凭外观猜型号。

黑白机只使用黑白抄表读数，彩色读数不适用；彩色机需要黑白、彩色两组累计读数。机型与设备实物不是同一对象，同型号可有多台设备。被设备引用的机型保留历史，不删除。

## R03｜Package / Package Version（套餐与版本）

套餐是价格条款：月租、每月免费黑白等价额度、超印单价，三项均须明确、非负；明确约定的零值有效，空白不等于零。

- 客户套餐用于应收：明确为标准套餐时不归属特定客户；专属套餐仅供所归属客户使用。“归属尚未知”不能冒充标准套餐。
- 供应商价格用于应付，必须明确供应商与价格版本；允许整个供应商价格部分尚未配置，不影响客户业务。
- 套餐可记录适配机型。当前平台能记录适配范围，但进场检查没有完整强制匹配；不匹配的资料应核实，不能声称已经符合约定。
- 每个套餐版本保留编码、版本号、生效日期和完整价格。重新议价创建新版本，不覆盖原版本的价格和额度。新版本不会自动切换历史订单，也不能仅凭日期猜测订单使用哪个版本。
- 名称、备注、启停状态、适配机型及生效日期可由管理员修正；价格、额度、超印单价和归属不得通过普通编辑改写。涉及历史解释变化时应保留依据。

## R04｜Order（订单）及一张订单的边界

一张订单代表一次完整租赁交易：一个客户、一个安装地址、一个供应商、一组共同的租期及结算方式，以及一条或多条套餐明细。

每条 OrderItem（订单明细）是一个确定的客户套餐版本及约定数量。数量为正整数，当前平台每行允许 1–999 台。同一订单可以是套餐 A × 10 台、套餐 B × 3 台。套餐必须适用于所选客户；不能只记套餐名称而遗漏版本。

不同客户、不同安装地址或独立的追加交易应另建订单。同一地址并不能证明属于同一订单；同一合同也可能支持多张订单，不能仅凭合同号合并。

新订单的客户、供应商、安装地址、开始日期、结算方式、至少一条有效明细必须明确。历史订单有缺失资料时保留“未知”，不能为补齐字段捏造供应商或地址。

订单状态为草稿、履约中、已结束、已取消。状态属于业务事实；看到文件或收到押金不能自动推断已履约。

## R05｜追加设备、分批履约与数量修正

- **追加交易**：客户另行增加租赁设备，必须新建订单，不能增加历史订单数量来代替。
- **分批进场**：履行原订单已约定但尚未交付的数量，设备归入原明细，无须新订单。
- **换机**：替换已有设备，按 R11 保留同一明细和替换关系，不当作追加交易。
- **录错更正**：管理员可以依据原始资料修正数量，但必须说明这是原交易更正。数量低于在用台数须提示并由管理员明确决定；押金应收随数量重新计算，不能据此推断额外押金已经收到或退还。
- 已经有关联设备记录的明细不得删除或切换套餐版本，即使设备已换机或撤机仍须保留。若确属新的交易或新价格安排，不能通过覆盖旧明细处理。
- 当前平台允许编辑数量和增加明细，不代表允许把追加交易塞回旧订单，见 D05。

## R06｜订单日期、默认三年与附件

下单日期、租赁开始日期、设备实际进场日期是不同事实。平台新建时下单日期取当天，管理员之后可修正。录入历史订单须采用原始下单日期；不能用本次录入日冒充历史发生日。

结束日期未另有约定时，默认开始日期加三年减一天，例如 2026-10-01 至 2029-09-30；2024-02-29 的同一默认算法结果为 2027-02-28。管理员可按明确约定调整，结束日期不能早于开始日期。默认日期应标明由规则推导，不冒充合同明示日期。

结算方式可按月或自然季度。新建平台表单默认月结；提取既有合同不能以默认值替代合同缺失信息。

合同文件与订单附件分开管理，均可暂缺。文件存在不等于内容一致；附件替换不能隐去仍待解决的矛盾。计划进场日期与实际进场日期不同，必填口径存在 D01 差异。

## R07｜押金

应收押金 = 本订单全部明细约定数量合计 × 2,000 元，按订单数量计算，不按当前在用或累计进场设备数计算。

押金收款日期用于登记已收事实；为空只能说明“尚无收款登记”，尤其历史数据不能据此断言实际未收。必须凭用户明确陈述或收款凭据登记真实日期，不能取合同日、今天或设备进场日代替。

现有范围不包含部分押金、分期收款、押金退款及抵扣。遇到这些资料保留来源并集中询问，不将部分到账登记成全额已收。换机、撤机或结束订单不会自动退押金。押金不并入租金和超印费，也不计入运营毛利。

## R08｜Printer 进场、身份与编码

一条设备记录承载一次明确的部署及其抄表历史，须关联订单明细、机型、实际进场日期和初始读数。进场后状态为运行中；无需先建供应商订单或补齐供应商价格。

明细在用台数低于约定数量才有进场余量；当前部署进度按运行中设备统计，不把已换机、已撤机历史记录累计成在用数量。余量不证明这是原订单未交付数量，仍需按 R05 区分追加与分批履约。

printerCode 是显示与查找用的设备编码：明确手填编码优先，其次供应商资产编码，再由系统生成 P0001 起的编码。供应商资产编码可空。不同供应商可能同码，设备编码不能独立作为设备身份；必须结合稳定设备记录、供应商、订单、地址、状态核对，见 D02。

已取消订单不可新增进场。当前平台没有同等阻止已结束订单进场，也不以订单起止日期自动限制进场日期；这些情况不等于已确认获准，应交管理员核实。

## R09｜entryDate、initial reading 与首月用量

entryDate 是实际进场日，不是签约日、计划日或照片拍摄日。黑白和彩色初始读数是设备进场时已有的累计表数，必须是非负整数；新机器也不能未经确认假定初始读数为零。

黑白机的彩色通道属于不适用，正常按零处理；如资料出现彩色计数，先核实机型与资料。彩色机的彩色初始读数不能省略或推测。

首期没有更早正式抄表时，以进场初始读数为基准：黑白用量 = 本期黑白累计读数 − 黑白初始读数；彩色同理。之后按相邻期累计差额计算。1 张黑白 = 1 黑白等价用量，1 张彩色 = 10 黑白等价用量。

如果首条记录跨过多个未抄月份，差额可能包含多个月用量，不能称为已核实的单月用量，不能擅自平均分摊、补零或倒推缺失表数，按 R10、R13 处理。

## R10｜MeterReading 新增、编辑和补录

同一设备同一业务年月只有一条正式抄表。业务年月是读数所对应的计费月份，不等于上传日期。记录不存在时新增；已存在且确需更正时编辑原记录，不删除重建，不产生第二条同月记录。

| 事项 | 客户扫码 | 管理员 / WorkBuddy 代录 |
|---|---|---|
| 时间范围 | 每月 1–3 日提交上一自然月 | 可录当前月和历史月份，不可录未来月份 |
| 设备状态 | 仅运行中 | 可补已换机、已撤机设备的在役历史 |
| 月份边界 | 遵循扫码开放月份 | 不早于进场月份，不晚于退场月份；含退场月 |
| 照片 | 必须有照片 | 可空，不凭空生成 |
| 修改 | 已提交后联系管理员 | 编辑须有调整说明，记录操作人 |

累计读数黑白、彩色分别核对：下界是目标月份之前最近一条正式抄表的累计数，没有则用初始读数；上界是目标月份之后最早一条正式抄表的累计数。允许相等，不能低于下界或高于上界。彩色机两组都须明确，黑白机不接受非零彩色抄表。

读数异常时不能把累计数当用量、交换颜色、加位数、归零或假定计数器回卷来消除异常。列出目标值、前后期值及对应月份，集中询问用户。

**历史联动待确认**：当前平台编辑实际使用原先保存的上期读数；补录或编辑不会自动调整后一期用量。见 D03。存在后期记录的历史变更应先明确受影响记录和结算处理方案，不能静默覆盖后期数据。未受影响的新月份录入照常进行。

## R11｜换机与撤机

换机只对运行中设备操作：原设备记为已换机，记录退场日；新建设备记录，实际进场日等于换机日，沿用原客户订单明细，关联上一台设备并记录新机型、新编码、新初始读数。新机从自己的初始读数开始，不能沿用原机累计数。原设备只能有一台直接后续替换设备，多次换机形成连续关系。

换机日期不得早于原设备进场日期。换机不是修改原设备型号来冒充新设备；不会迁移或删除原机抄表。供应商变化必须核实，不能从新编码自动推断供应商或成本。

撤机只对运行中设备操作，明确退场日期且不早于进场日期；状态变为已撤机，保留全部历史。已换机、已撤机设备不再普通编辑或删除，但可按 R10 补录在役月份抄表。

当前换机、撤机并不自动采集最后读数；如退场月需结算，应取得原机实际读数补录，不能凭新机读数推算。退场日不计租金，新机进场日计租金。

## R12｜Order 结束

结束订单只将订单标为已结束，不自动撤机、不删除抄表、不结清费用、不退押金。已取消订单不能直接执行结束操作。

仍有运行中设备时应提示台数；管理员明确要求结束并已知设备仍在用的，可执行，不反复确认。若意图仅为“现场停止租赁”，须一次性核实订单结束、各设备撤机日期和最后抄表是否都要处理。

租期到期不等于已结束，订单结束也不等于设备已退场。当前计费按设备实际进退场日期，不自动按订单结束日截断。

## R13｜Settlement 结算原则

最小单位是“一台设备 × 一个自然月”。免费额度逐设备、逐月份独立，不能跨设备共享，也不能将季度总用量减季度总额度后统一计超印。

1. 在场天数 = 当月实际在场日数，进场日包含、退场日不包含；与当月无重叠时不产生该月金额。
2. 折算月租 = 套餐月租 × 在场天数 ÷ 当月自然天数，四舍五入保留两位。
3. 折算免费额度 = 月免费额度 × 同一比例，四舍五入保留两位。
4. 等价用量 = 黑白用量 + 彩色用量 × 10。
5. 超印量 = 等价用量减折算额度，最低为零，保留两位；超印费 = 超印量 × 超印单价，四舍五入保留两位。
6. 当月金额 = 已折算月租 + 已计算超印费。按上述步骤取舍，不能最后统一取舍替代。

客户侧与已明确的供应商侧分别套用各自价格。先逐台逐月计算，再汇总订单。自然季度为 Q1：1–3 月、Q2：4–6 月、Q3：7–9 月、Q4：10–12 月；季度中途进退场仍由各月折算，不按滚动三个月结算。

例：30 天月份进场 11 天，月租 450、月额度 10,000、等价用量 11,000、单价 0.03，则折算月租 165.00、额度 3,666.67、超印量 7,333.33、超印费 220.00，应收 385.00。两台条件相同的设备合计 770.00。

当前平台仅针对已有抄表给出实时运营摘要，并选择最新月份或季度展示，不是正式结算单。缺少月份或设备抄表时不能认定整单已经算齐，更不能将缺抄当成零用量。跨月漏抄差额不自动分摊；需要取得实际资料或人工明确处理，未明确前标记不完整。

供应商价格缺失时，客户应收仍可计算；供应商应付及毛利为“暂不可计算”，不是零。汇总涉及的任一设备或月份缺供应商价格时，不将已知部分伪装成完整应付或毛利。缺抄与缺供应商价格是不同缺口，须分别标明。

抄表、设备日期等更正可能影响实时金额；“保护历史”不意味着金额已经锁账。当前范围没有开票、回款核销、结算封账或正式财务账单。

## R14｜历史保护与管理员修改权

管理员可修正订单供应商、地址、起止日期、结算方式、下单日期、状态、备注和收款日期；客户及订单号不通过普通编辑改变。数量按 R05 处理。已有设备的明细保留套餐版本和关联；有设备历史的订单不删除。

运行中或草稿设备的编码、机型、进场日期、初始读数和备注当前允许修正，所属订单明细不改。已经有抄表的设备涉及日期或初始读数修正时，应核实历史影响，不能承诺平台会联动修复全部历史用量。

管理员最终修改权不等于可以改写套餐历史价格、删除换机链或绕过抄表唯一性。当前平台仍允许删除尚未换机或撤机的设备并连带删除其抄表；本台账方案不自动执行这种历史删除，见 D06。

台账与 WorkBuddy 新增的保留来源、修改说明和待核实标记是运营保护措施，不宣称原平台已有完整审计或附件版本归档。

## R15｜可空、可推导与不得猜测

| 类型 | 处理 |
|---|---|
| 可为空 | 主体税号、银行、联系人、备注；合同与订单附件；供应商资产编码；管理员抄表照片；尚未登记的押金收款日期；缺失的供应商价格 |
| 特定历史资料可空 | 原订单供应商、地址、日期等无法证实时保留未知并标记；不以历史可空推导新订单也可任意缺资料 |
| 可按规则推导 | 未另有约定的新租期默认结束日期、约定数量的押金应收、已确定读数的用量、在场天数、季度归属、已知条件下的结算与部署进度 |
| 不得猜测 | 主体身份、客户类型、供应商、实际安装地址、套餐版本与价格、数量、实际进退场日期、初始或累计读数、照片所属设备及业务月份、押金到账事实与日期 |

自动编号不等于推断外部原始单号。标准套餐空归属是已确认的适用范围，供应商成本未知、收款未知及“无需彩色通道”也各有不同含义，不能统一用零表示。

## R16｜资料缺失、冲突与写入原则

相同文件、同一照片或相同事实重复提交不重复建档。新增或更新前先查已有记录；名称或设备码只能作为候选匹配，不是充分依据。

合同、订单、截图、口述互相矛盾时，记录冲突字段、双方值、来源位置和受影响对象。不能默认“最近上传的”“文件名最新的”或“看起来正式的”胜出。用户明确指出某资料为修订或纠错并说明适用对象时，可据此更新，保留原来源和解释。

把关键缺失与冲突一次性集中询问；只询问影响身份、关联、金额、时间、生命周期和写入正确性的事项。资料充分、规则明确且无冲突时直接写入，不重复请求确认。独立且完整的对象可先处理，受冲突影响的关联操作暂缓。

## R17｜文档规则与当前实现存在差异

以下差异尚未裁决；WorkBuddy 不以其中一侧静默替代另一侧。

| 编号 | 已确认规则或文档表述 | 当前行为及处置 |
|---|---|---|
| D01 | TASK 11 建议不再维护订单明细计划进场日期 | 当前订单录入仍要求该日期。台账暂保留独立可空字段并标记缺失为待核实，不拿开始日或实际进场日凑数；是否取消必填待确认 |
| D02 | TASK 11 人工修正允许不同供应商使用相同设备编码 | 当前新增和换机遇到任何运行中同码设备都阻止继续，历史同码不拦。台账先识别真实设备，不自动改码或合并；确属跨供应商同码的处理待确认 |
| D03 | TASK 19 描述编辑下界取目标月份前最近抄表 | 当前编辑沿用原保存的上期值；历史补录和修改不联动更新下一期的上期值与用量。涉及后期记录时暂缓受影响写入，集中确认重算与复核方案 |
| D04 | 客户、供应商、设备及订单的自动编码不复用已删除编号 | 当前仅从仍存在的编号取下一个，最高编号删除后可能复用。台账保留已用编号和停用记录，禁止自动硬删除；不能承诺原历史编号完整 |
| D05 | 追加设备必须新订单 | 当前普通编辑能增加旧订单数量和明细，无法区分更正与追加。按 R05 识别意图，不把可编辑理解为可追加 |
| D06 | 历史保护要求保留设备和抄表事实 | 当前尚未换机或撤机的设备仍可删除，连带抄表也会丢失。WorkBuddy 不自动删除此类记录；误录如何归档或作废待人工决定 |

另有已明确被后续确认替代的旧建议，不作为开放争议：设备编码全局唯一已被取消；季度不再仅作展示，而是汇总各月；订单状态业务名称为“履约中”；历史供应商无法唯一判定时保持未知，地址不编造。

## R18｜仍需人工确认的运营事项

1. D01、D02：计划进场日期的最终必填口径，以及跨供应商同码设备的实际台账登记方式。
2. D03：历史补录或更正后，是否及如何重算后一期、复核相关月度与季度金额；已对外报账的金额如何留痕。确认前不自动批量重算。
3. 多月漏抄且无法取得逐月实际读数时，如何分配用量与结算；不自行平均分摊。
4. 已结束订单继续进场、订单日期外的设备履约、换机时供应商变化的业务归属；不能把现有操作能力当作业务结论。
5. 部分押金、退款、抵扣及特殊押金金额；这些不在现有规则范围，不能靠管理员普通编辑臆造支持。
6. D06 及已有抄表后修改初始读数、机型或进场日期的历史保护方式。

上述事项不妨碍资料完整、没有触及争议的正常订单、进场和抄表业务。
