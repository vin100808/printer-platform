# WorkBuddy 运营台账设计（企业微信智能表方案）

> 本文档把《PRINTING_OPERATIONS_RULES.md》的业务规则映射为「企业微信智能表 + WorkBuddy」的轻量运营台账。
> 分工原则：**智能表只存真实业务事实；能算出来的一律不存**，由智能表公式或 WorkBuddy 现算。不为尚未发生的特殊情况提前设计能力。
> 不复制 Web 平台的历史技术模型（Location、FrameworkContract、SupplierOrder、SupplierOrderItem、Settlement、Deposit、AuditLog 等一律不进智能表）。

---

## 总体结构（8 张表，不再增减）

```
客户 ──┐                    ┌── 供应商
       ├── 订单 ── 订单明细 ──┤
套餐 ──┘        │            └── 套餐
机型库 ─────────┴── 设备 ── 抄表记录
```

主链路：客户 → 订单 → 订单明细 → 设备 → 抄表记录。辅助：供应商、套餐、机型库。

**审计字段统一约定**：不为每张表维护资料状态 / 来源说明 / 缺失项 / 冲突说明 / 修改说明 / 操作人 / 录入时间 / 更新时间等治理字段。一律依赖智能表自带的 Record ID、创建时间、修改时间。业务表只保留轻量的「备注」，个别表保留确有价值的字段（订单的来源附件、抄表的调整说明）。

## 表 1｜客户

**业务用途**：记录所有租赁客户的主体资料。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 客户编码 | 必填，自动生成 | C0001 起递增，创建后不改 |
| 客户名称 | 必填 | 查重主键 |
| 状态 | 必填 | 正常 / 停用 |
| 客户类型 | 可选 | 内部 / 外部；无运营价值可不填，不得因缺失阻塞任何流程 |
| 税号 / 注册地址 | 可选 | 注册地址是工商地址，与安装地址无关 |
| 银行名称 / 户名 / 账号 | 可选 | |
| 联系人 / 联系电话 | 可选 | |
| 备注 | 可选 | |

- **关联**：被「订单」「套餐（客户专属）」引用。
- **查重规则**：按客户名称查重；同名不同主体由人工确认后再建。
- **新增 / 更新规则**：基础资料可更新；有订单或套餐引用的客户不删除，只停用。

## 表 2｜供应商

**业务用途**：记录设备与服务的上游供应商。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 供应商编码 | 必填，自动生成 | S0001 起递增 |
| 供应商名称 | 必填 | 查重主键 |
| 状态 | 必填 | 正常 / 停用 |
| 税号 / 注册地址 / 银行资料 | 可选 | |
| 联系人 / 联系电话 / 服务区域 | 可选 | |
| 备注 | 可选 | |

- **关联**：被「订单」「套餐（供应商套餐）」引用。
- **查重 / 更新规则**：同客户表。

## 表 3｜套餐

**业务用途**：统一存放客户套餐与供应商套餐的价格条款及版本历史。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 套餐编码 | 必填 | （套餐编码 + 版本）唯一 |
| 版本 | 必填 | 整数，从 1 开始 |
| 套餐名称 | 必填 | |
| 套餐侧别 | 必填 | 客户套餐 / 供应商套餐 |
| 归属客户 | 客户专属套餐必填 | 为空 = 标准套餐 |
| 归属供应商 | 供应商套餐必填 | |
| 月租（元/月） | 必填 | |
| 免费额度（BW Equivalent/月） | 必填 | |
| 超印单价（元/BW Equivalent） | 必填 | |
| 生效日期 | 必填 | |
| 适配机型 | 可选 | 关联机型库，可多选 |
| 状态 | 必填 | 正常 / 停用 |
| 备注 | 可选 | |

- **查重规则**：（套餐编码 + 版本）唯一。
- **新增 / 更新规则**：价格创建后不可修改；重新议价 = 同编码新建版本，旧版本保留可停用。**供应商套餐价格由运营方自行维护**，不向供应商开放。

## 表 4｜机型库

**业务用途**：打印机标准产品目录。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 品牌 | 必填 | （品牌 + 型号）唯一 |
| 型号 | 必填 | |
| 设备类型 | 必填 | 黑白 / 彩色；决定抄表是否要彩色读数 |
| 状态 | 必填 | 正常 / 停用 |
| 备注 | 可选 | |

- **查重规则**：品牌 + 型号组合查重。被设备引用的机型不删除。

## 表 5｜订单

**业务用途**：一张订单 = 一次完整租赁交易。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 订单号 | 必填，自动生成 | YYYYMMDD + 当日两位序号，全局唯一 |
| 客户 | 必填 | 关联客户表；**创建后不可改** |
| 供应商 | 必填 | 关联供应商表 |
| 安装地址 | 必填 | 手填文本 |
| 开始日期 | 必填 | |
| 结束日期 | 可选 | 默认 = 开始日期 + 3 年 − 1 天，可改 |
| 结算方式 | 必填 | 按月结算 / 按自然季度结算 |
| 押金应收 | 自动计算 | = 全部明细数量合计 × 2,000 元，固定规则，不做人工改价 |
| 押金收款日期 | 可选 | 空 = 尚未登记收款；有日期 = 已全额收到 |
| 下单日期 | 必填 | 默认当天 |
| 状态 | 必填 | 草稿 / 履约中 / 已结束 / 已取消 |
| 合同文件 | 可选 | 附件 |
| 订单附件 | 可选 | 附件（与合同文件独立） |
| 备注 | 可选 | |

- **自动计算（不人工维护）**：押金应收、明细合计数量、已部署合计、部署状态。
- **查重规则**：订单号唯一；「同客户 + 同地址 + 同开始日期」高度疑似重复，建单前查重确认。
- **新增 / 更新规则**：新增设备必须新建订单；客户不可改；有设备的明细行不可换套餐、不可删行；结束订单只改状态不动设备；已取消订单不可再进场；有设备的订单不删除。

## 表 6｜订单明细

**业务用途**：订单内「套餐 × 数量」的逐行约定；设备进场的挂载点。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 所属订单 | 必填 | 关联订单表 |
| 套餐 | 必填 | 关联套餐表（对该订单客户可用的客户套餐） |
| 数量 | 必填 | 整数 ≥ 1 |
| 备注 | 可选 | |

（没有计划进场日期：订单有开始日期，设备有实际进场日期，足够。）

- **自动计算（不人工维护）**：已部署台数（本明细下运行中设备数）、部署状态（未部署 / 部分部署 / 已部署）。
- **查重规则**：同一订单内同套餐应合并为一行。
- **新增 / 更新规则**：已有设备进场的明细行不可换套餐、不可删除；新增明细行随时可加。

## 表 7｜设备

**业务用途**：打印机台账，业务最核心的一张表。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 设备编码 | 必填 | 唯一一套编码：供应商有机身编号就直接用它，没有则自动生成（P0001 起）。**不同供应商允许同号**；真正身份是 Record ID，编码仅作日常识别 |
| 所属订单明细 | 必填 | 关联订单明细；客户、地址、套餐由此自动追溯 |
| 机型 | 必填 | 关联机型库 |
| 进场日期 | 必填 | 计费与用量计算起点 |
| 退场日期 | 可选 | 撤机 / 换机时填写 |
| 黑白初始读数 | 必填 | 首期用量 = 首期抄表 − 初始读数 |
| 彩色初始读数 | 彩色机必填 | 黑白机恒为 0 |
| 状态 | 必填 | 运行中 / 已换机 / 已撤机 |
| 上一台设备 | 可选 | 换机链：指向被替换的旧设备 |
| 抄表二维码 | 可选 | 免登录抄表入口链接（如沿用 Web 抄表页） |
| 备注 | 可选 | |

- **关联**：订单明细、机型、上一台设备（自关联）；下挂「抄表记录」。
- **不应重复保存**：客户名、安装地址、套餐、供应商、价格等一切可关联得到的字段。
- **查重规则**：编码不做唯一约束。WorkBuddy 查设备时结合 Record ID、所属订单、供应商、机型、状态判断；新建时若与运行中设备同编码，提示确认一次即可。
- **新增 / 更新规则**：进场只在「已部署 < 数量」的明细下进行，创建即「运行中」；换机 = 旧机已换机 + 退场日期，新机运行中 + 上一台设备指向旧机 + 新初始读数，订单明细沿用原机；撤机 = 已撤机 + 退场日期；已换机 / 已撤机设备不物理删除、不修改。

## 表 8｜抄表记录

**业务用途**：每台设备每个自然月的正式读数。只存业务事实，衍生值一律现算。

| 字段 | 必要性 | 说明 |
|---|---|---|
| 设备 | 必填 | 关联设备表；（设备 + 年 + 月）唯一 |
| 年份 / 月份 | 必填 | 业务月份（自然月） |
| 本期黑白累计读数 | 必填 | 表显累计值 |
| 本期彩色累计读数 | 彩色机必填 | 黑白机不填 |
| 抄表照片 | 客户扫码必传 / 后台补录可选 | |
| 状态 | 必填 | 已提交 / 已调整 |
| 调整说明 | 编辑时必填 | 修正必须留痕 |
| 操作人 | 可选 | 智能表方便记录就记 |

**以下一律不存台账**，由智能表公式或 WorkBuddy 现算：

- 上期读数、黑白 / 彩色用量、BW Equivalent 用量、一切结算金额。
- 推导规则：首期用量 = 本期累计 − 设备初始读数；后续期 = 本期累计 − 上一期正式抄表。若智能表无法可靠自动查找上一期，由 WorkBuddy 查询前一期后计算，**不要为了公式好写而复制一套容易失真的字段**。

- **查重规则**：（设备 + 年 + 月）唯一；同月已有记录只能编辑原记录。
- **新增 / 更新规则**：本期读数 ≥ 上一期读数（上一期 = 之前最近一条正式抄表，缺省为初始读数）；目标月之后已有抄表时本期读数 ≤ 下一期读数；月份须在在役期间内且非未来月；编辑 = 改读数 + 必填调整说明 + 状态转「已调整」，不删除重建；**修改历史读数后，后续期的用量按最新累计读数实时重算**（当前无封账 / 开票锁定）。

## 结算的实现方式

结算由 WorkBuddy 按《PRINTING_OPERATIONS_RULES.md》第 5 章**现算现报，不写回台账**：

1. 取设备最近一个抄表月份（季度单取最近季度内各月）；
2. 按月算在场天数（进场计入、退场不计）→ 折算月租与免费额度 → 超印 → 当月金额；
3. 客户侧用订单明细的客户套餐；供应商侧用供应商套餐（缺失报「未配置」，不阻塞客户侧）；
4. 免费额度逐设备逐月独立；季度 = 季度内各月相加；订单 = 同期各台相加。

## 推荐视图（初期只保留这些）

| 视图 | 所在表 | 筛选条件 |
|---|---|---|
| 履约中订单 | 订单 | 状态 = 履约中 |
| 待收押金 | 订单 | 押金收款日期为空 且 状态 ≠ 已取消 |
| 待进场 | 订单明细 | 已部署台数 < 数量 且 所属订单状态 ∈（草稿, 履约中） |
| 在用设备 | 设备 | 状态 = 运行中 |
| 待抄表 | 设备 | 状态 = 运行中 且 本期业务月份（上一自然月）无抄表记录 |
| 已结束订单 | 订单 | 状态 = 已结束 |
| 待核实（可选） | 各业务表 | 备注或专用标记字段标注待人工核实的记录 |

其他视图（历史设备、即将到期、本期已抄等）以后真实运营需要时再增加。
