# 企业微信智能表｜打印机运营台账方案

版本：TASK 20，2026-09-23。本文是设计规格，尚未创建智能表，也未验证具体账号的关联、公式、权限或 WorkBuddy 连接能力。

业务依据：[PRINTING_OPERATIONS_RULES_CODEX.md](PRINTING_OPERATIONS_RULES_CODEX.md)，操作依据：[WORKBUDDY_PRINTING_SKILL_CODEX.md](WORKBUDDY_PRINTING_SKILL_CODEX.md)。本方案只使用八张业务表，不复制 Location、FrameworkContract、SupplierOrder、SupplierOrderItem 等历史技术模型。

## L00｜共同约定

- 每行有不可变的“记录标识”，关联一律指向该标识。客户编码、订单号、设备编码是业务检索字段，尤其设备编码不能代替唯一身份。
- 日期按中国业务日记录，格式 YYYY-MM-DD；业务年月用 YYYY-MM，独立于录入时间。时间默认 Asia/Shanghai，是本台账选定口径；原平台按其运行环境当地时间处理抄表窗口。
- 金额为人民币，月租两位、免费额度两位、超印单价最多四位小数。累计读数为非负整数；公式及取舍按 R13，不能用显示格式代替真实取舍。
- 以下“必要”指正式业务记录所需；关键字段缺失时不捏造值。历史原始记录允许缺失时标记“待核实”，不视为完整新业务。尚不能确定身份的资料保留在本次处理清单，不创建虚构主体或正式抄表。
- 各表共同必要字段：记录标识、资料状态（完整 / 待核实）、来源说明、录入时间、最近更新时间。来源可为文件名称及页码/表名/行号，也可为用户明确陈述及时间。
- 各表共同可选字段：来源附件、缺失项、冲突说明、修改说明、操作人、备注。发生更正时修改说明及操作人必要；来源文件可为多个，保留冲突旧资料，不覆盖掉争议证据。
- “资料状态”不是订单或设备的业务状态，也不是审批流程。来源信息和修改记录是本方案新增的运营字段，不声称原平台已有。
- 信息未提供不能清空已有值；明确要求清空且规则允许时才清空。未知与零、未收、未进场、不适用分开表达。
- 自动编号建议沿用 C / S / P 编码及日期订单号；已用编号保留，禁止为腾编号删除记录。历史外部单号保存在“外部订单号”，不强改现有内部订单号。并发新增前后均须复查；无法可靠分配时不得猜一个编号写入。
- 公式、关联查找及汇总可由智能表或 WorkBuddy 实现；必须验证结果一致后启用。跨记录前后期查找与历史影响检查不能假定普通单行公式会自动完成。不能保证安全刷新时，暂不输出完整结算。

关联主线：客户 → 订单 → 订单明细 → 设备 → 抄表记录；订单关联供应商，明细关联客户套餐版本，设备关联机型及可选供应商价格版本。

## L01｜客户

用途：租赁服务客户主体档案，对应 R01。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 客户编码；客户名称；客户类型（内部 / 外部）；状态（启用 / 停用） |
| 可选 | 税号、注册地址、银行名称、银行户名、银行账号、联系人、联系电话 |
| 关联 | 订单的客户；专属客户套餐的归属客户 |
| 可计算 | 订单数、运行中设备数 |
| 不重复保存 | 订单地址、设备清单和套餐价格；统计使用关联，不手抄第二份 |

查重：已有记录标识或客户编码优先；有税号时核对税号；名称用于检索候选。名称相同而主体不明不合并，名称不同但税号相同也先核实更名事实。

新增 / 更新：确认主体后新增；基础资料可依据明确事实更新，编码不改；有关联业务的客户只停用，不删除。类型未知须询问，不能默认外部。

## L02｜供应商

用途：设备及服务上游主体，对应 R01、R13。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 供应商编码、供应商名称、状态（启用 / 停用） |
| 可选 | 税号、注册地址、银行名称、银行户名、银行账号、联系人、联系电话、服务区域 |
| 关联 | 订单供应商、供应商侧套餐归属供应商 |
| 可计算 | 关联订单数、关联运行中设备数；历史供应商不明确的设备不强行归入统计 |
| 不重复保存 | 每张订单的价格和地址，不在主体表保存一个通用成本代替不同版本 |

查重：标识、编码、税号、名称候选核对规则与 L01 相同。

新增 / 更新：有明确主体即可建档，不要求先有成本价格；资料补充更新原行，有历史引用时只停用。名称无法区分的同名供应商须询问。

## L03｜套餐

用途：统一存放明确的客户或供应商价格版本。供应商侧仅是可选成本资料，绝不要求建立供应商订单。对应 R03。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 套餐编码、版本号（正整数）、套餐名称、侧别（客户 / 供应商）、月租、月免费等价额度、超印单价、生效日期、状态（启用 / 停用） |
| 条件必要 | 客户侧须明确适用范围（标准 / 客户专属）；专属时归属客户必要；供应商侧归属供应商必要 |
| 可选 | 适配机型（多关联）、议价依据附件；标准套餐的归属客户为空 |
| 关联 | 归属客户或供应商、适配机型；被明细或设备引用的确定版本 |
| 可计算 | 展示名称＝套餐编码＋版本号＋名称；被引用次数 |
| 不重复保存 | 不另建一份可覆盖历史的“当前价格”；不在每台设备手填客户套餐三项价格 |

查重键：“侧别＋套餐编码＋版本号”。客户和供应商原先分别维护，不能因同码同版而合并；名称和相同价格仅是相似候选，不是同一版本证据。

新增 / 更新：已有相同键且内容一致则复用；价格变化走新版本，版本号取同侧同编码已用最大版本加一，不覆盖旧版。缺少价格不能建立零价占位套餐；整个供应商价格关联可以为空。普通编辑仅修正 R03 允许的非价格资料，保留依据。

## L04｜机型库

用途：标准机型目录，对应 R02。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 品牌、型号、设备类型（黑白 / 彩色）、状态（启用 / 停用） |
| 可选 | 型号来源资料、备注 |
| 关联 | 套餐适配机型、设备机型 |
| 可计算 | 在用设备数 |
| 不重复保存 | 设备编码、进场日期、累计读数不属于机型资料 |

查重：品牌＋型号组合；仅做去首尾空格等无损规范化，不擅自合并不同后缀型号。

新增 / 更新：明确型号和类型后新增。纠正型号或类型前核对已关联设备，若会改变彩色读数解释须人工处理。有引用不删除。

## L05｜订单

用途：一次完整租赁交易，对应 R04–R07、R12。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 订单号、客户关联、供应商关联、安装地址、下单日期、开始日期、结束日期、结算方式（月结 / 自然季度）、状态（草稿 / 履约中 / 已结束 / 已取消） |
| 可选 | 外部订单号、合同编号、合同文件、订单附件、押金收款日期；历史供应商等未知按 L00 保留缺口 |
| 关联 | 客户、供应商、订单明细（反向）；从明细追溯设备 |
| 可计算 | 总约定台数、押金应收、在用台数、尚无押金收款登记标记、最近可得结算期间及完整性 |
| 不重复保存 | 客户税号、供应商银行、机型资料、逐台读数；不重复手填押金应收或每月应收金额 |

结束日期可按 R06 推导并记录推导来源；具体合同明确约定优先。押金应收＝明细数量合计×2,000。收款日期为空显示“未登记 / 待核实”，日期非空显示“已登记收款”，不新增部分收款能力。

查重：内部订单号精确定位；外部订单号须结合客户与来源。无可靠单号时用客户、供应商、安装地址、租期、套餐明细、文件上下文查候选，不能仅因同址同客户自动合并。

新增 / 更新：追加交易新建；分批履约更新设备而非改订单数量。更正旧单须明确更正依据，客户和内部订单号不改；有设备历史不可删除。结束状态不推导撤机、回款或退款。日期、地址或供应商更正需说明受影响设备，不能隐藏历史事实。

## L06｜订单明细

用途：记录订单约定的套餐与设备数量，连接订单和实际设备，对应 R04、R05、D01。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 订单关联、明细序号（订单内唯一）、客户套餐版本关联、约定数量（正整数，兼容当前每行 1–999） |
| 可选 | 计划进场日期、原文件行号、备注；计划日期为空时标记 D01 待核实，不代填 |
| 关联 | 订单、客户侧套餐确定版本、设备（反向） |
| 可计算 | 运行中台数、余量＝约定数量−运行中台数、待进场数＝最大值（余量，0）、部署状态 |
| 不重复保存 | 套餐月租与额度、客户地址、每台实际进场日期 |

查重：已有明细标识优先，其次订单＋明细序号及来源行。不能把订单＋套餐版本当作唯一键，因为原单可有多行同套餐；模糊匹配需询问，不自动合并数量。

新增 / 更新：新订单按明确原始行创建；已有明细的数量仅作有依据的纠错。有任何历史设备关联时不可更换套餐版本或删除。数量低于运行中台数须明确提示，余量为负保留异常，不隐藏为“正常满额”。

## L07｜设备

用途：每台部署设备及生命周期历史，对应 R08、R09、R11、R14。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 设备编码（printerCode）、订单明细关联、机型关联、实际进场日期（entryDate）、黑白初始读数、彩色初始读数或黑白机不适用零值、状态（草稿 / 运行中 / 已换机 / 已撤机） |
| 条件必要 | 已换机或已撤机的退场日期；换机新记录的上一台设备关联 |
| 可选 | 供应商资产编码、供应商价格版本关联、历史实际供应商关联、备注 |
| 关联 | 从明细追溯订单及客户套餐；关联机型、前机；可选关联供应商侧套餐确定版本 |
| 可计算 | 客户、订单号、安装地址、当前订单供应商、设备类型、后续替换机、最近抄表年月、指定月在场天数、待抄标记 |
| 不重复保存 | 客户基本资料、客户价格、逐月抄表结果、订单地址的可编辑副本 |

“历史实际供应商”仅在来源明确且订单供应商为空或不能表达历史事实时使用；否则留空、从订单查找。与订单供应商或供应商价格归属冲突时标记，不静默选择。新增这一字段是台账历史表达方案，不是恢复供应商订单模型。

供应商价格版本直接关联设备，是轻量台账对历史成本关系的映射，不声称原平台的新进场页支持直接选成本套餐。已有历史结算的设备不能直接切换供应商价格重算过去；价格生效区间变化超出现有八表简单关联能力时须另行确认，不新增隐藏规则。

查重：记录标识最可靠；设备编码、资产编码结合供应商、订单、地址、机型、在役日期检索。多条候选或 D02 跨供应商同码时集中询问，不合并、不擅自换码。相同实物再次部署不能仅凭编码接回旧记录，须核实部署事实。

新增 / 更新：原单余量进场新建设备；换机保留原设备、新建替换设备并关联；撤机只更新原记录状态及退场日期。普通资料更正仅在允许状态下进行，所属明细不可改。涉及已有抄表的日期、初始读数、类型变化走待核实处理，不自动删除设备。

## L08｜抄表记录

用途：唯一正式月度抄表，不另建测试或手工第二套记录，对应 R09、R10、R13、D03。

| 字段组 | 字段及约束 |
|---|---|
| 必要 | 设备关联、业务年月、当前黑白累计读数、当前彩色累计读数（黑白机为不适用零值）、状态（已提交 / 已调整）、提交时间 |
| 条件必要 | 编辑后的调整说明和操作人 |
| 可选 | 抄表照片、原始采集日期、原始上期黑白读数、原始上期彩色读数、原始黑白用量、原始彩色用量、原始等价用量；原始字段仅用于有既有导入值时保留来源 |
| 关联 | 设备；前一条和后一条业务月份记录按设备及年月查询 |
| 可计算 | 上期月份及读数、三种用量、在场天数、折算月租与额度、超印量与费用、客户应收、已知成本时供应商应付及毛利、数据完整性 |
| 不重复保存 | 客户、供应商、套餐价格的手填副本；不得同时维护两份可编辑“月用量” |

查重键：设备记录标识＋业务年月。年月必须由资料或明确用户指令确定，不能从文件上传时间推断。

新增 / 更新：按 R10 验证前后期边界和在役月份。已存在且事实相同则跳过；不同则先判定明确纠错还是冲突，再编辑原记录。编辑不改变设备和业务年月；月份或设备录错涉及正式记录归属，须人工指定纠错方式，不自动删建。

正常顺序录入可按前期读数计算；缺中间月份、历史补录或已有后期记录时，显示“历史影响待核实”。原始导入值与复算值不一致要保留双方。**D03 未裁决前，不启用会自动改写后期结果的跨行动态公式，也不将复算候选作为正式结果。** 可在本次报告列出候选差额，待用户明确方案后处理。

## L09｜推荐视图与汇总

所有日期视图显示明确目标业务年月，不能只显示含糊的“本月”。视图是派生结果，不再复制成另一张事实表。

| 视图 | 筛选与展示口径 |
|---|---|
| 待收押金 | 草稿或履约中订单、押金应收＞0、押金收款日期空；标题说明为“尚无收款登记”，保留未知提示；已结束或取消的缺登记记录另在待核实视图可见 |
| 待进场 | 草稿或履约中订单下待进场数＞0 的明细，显示计划日期及是否已知；余量只是候选任务，仍按 R05 判断是否原单未交付 |
| 在用设备 | 设备状态为运行中；显示订单状态，突出“订单已结束但设备仍在用” |
| 本月待抄 | 目标为当前自然月，与该月有正数在场天数且没有该月正式抄表的设备；包括本月已换机或已撤机设备。月内只作计划，不能一律认定逾期 |
| 平台本期待抄 | 1–25 日目标为上一自然月，26 日起目标为当前月，沿用平台本期月份；设备范围同上，不只取当前运行中设备 |
| 历史待补抄 | 按选定历史年月列在场＞0 且无正式抄表的设备，包含已结束订单及历史设备 |
| 已结束订单 | 订单状态为已结束，展示在用台数、押金登记、缺抄及待核实情况，不显示“自动结清” |
| 待核实 | 资料状态为待核实，或存在缺失、冲突、负余量、结算不完整、历史影响未处理的记录 |
| 月度 / 季度运营汇总 | 按明确期间、逐机逐月的已核实结果汇总，再按订单汇总；显示应有设备月份数、已抄数、缺抄清单、价格缺口、金额完整性 |

季度汇总只加总月度结果，不共享额度，不跨季度混合。设备当月在场为零时不纳入应计费数量；退场月仍允许补抄，但可能是零天、无金额。

供应商价格任一缺失则完整应付及毛利留空，已知部分如展示必须明确标成“已知部分”。客户缺抄或读数待核实亦不得宣称完整应收。八表内不新增结算单、收款核销或发票表。

## L10｜落地前检查与规格验收

实际配置时先验证稳定关联、前后期检索、唯一性防重、金额取舍、来源保留、回读能力；本 TASK 不配置连接或真实数据。能力不足时报告具体缺口，不退回用猜测或覆盖历史完成写入。

| 案例 | 预期结果 |
|---|---|
| 原单 A×10、B×3，先交 5 台 | 两条明细，设备分别关联明确明细；未交量保留，不另造追加交易 |
| 原单已履行，客户另加两台 | 新订单，旧数量不改；对应押金应收 4,000 |
| 30 天月在场 11 天，R13 示例 | 单台应收 385.00，两台 770.00，不共享额度 |
| 7 月用量低于免费额度、8 月超额 | 不能用 7 月剩余额度抵扣 8 月超印 |
| 供应商价格缺失 | 应收照常；应付、毛利未知，不显示零 |
| 季度只收到两个月抄表但三个月均在场 | 只展示已知部分，列缺失月份，不标完整季度 |

| 跨供应商同设备码 | 查询到不同候选，不自动合并；按 D02 处理 |
